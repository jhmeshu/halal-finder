# 08 — Product Decision Log

| Decision | Current direction | Reason / caveat |
|---|---|---|
| Initial format | Mobile-friendly installable web app (PWA) | Lowest-cost way to test across devices. |
| Budget | Free-first; small domain spend optional | Founder currently has little/no budget for recurring costs. |
| Geographic design | Global data model, staged city coverage | Avoid empty, low-quality global listings. |
| Initial commercial test | London is a working hypothesis | Validate with users and businesses before committing. |
| Asian coverage | Include selected Asian travel destinations | Important to travellers; coverage quality matters more than number of countries. |
| Core categories | Restaurants, groceries, halal meat/butchers | Core discovery needs for residents and travellers. |
| Scanner | Barcode lookup + ingredient screening in MVP | Camera scanning can follow after core lookup works. |
| Trust model | Evidence categories with source and freshness | Avoid false confidence and pay-to-verify incentives. |
| Monetization | Paid business profiles, sponsored placement, optional ad-free premium, relevant ads, later referrals | Validate willingness to pay before building billing. |
| Delivery | Later, not MVP | Operational and regulatory complexity. |
| Native apps | Defer | App-store fees and extra maintenance are not justified before validation. |
| Real data | Only licensed/sourced listings; sample data stays visibly fictional | Accuracy, trust and licensing. |
